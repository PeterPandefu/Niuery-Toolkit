## 3. 前端内部分层依赖图

```mermaid
flowchart TB
    subgraph Entry["入口层"]
        MAIN["main.tsx（窗口分派）"]
        APP["App.tsx"]
    end
    subgraph Layout["布局层"]
        SB[Sidebar] --- TP[ToolPanel] --- SD[SearchDialog] --- GD[SettingsDialog] --- SBAR[StatusBar] --- LP[LogPanel] --- AT[AppTitleBar] --- SA[SkinAtmosphere]
    end
    subgraph Core["核心层"]
        REG[tool-registry 注册表]
        STORE[8 个 Zustand Store]
        HOOKS[Hooks]
        REGDB[(types/tool.ts 类型)]
    end
    subgraph Tools["工具层（50 工具）"]
        TOOLSIMPL[tools/* 组件]
    end
    subgraph Lib["纯函数库层（lib/）"]
        UTILS[converter/codec/generator/text-utils 等]
        INFRA[logger/theme/i18n/file-save/resources/api-client 等基础设施]
    end

    MAIN --> APP --> Layout
    Layout --> Core
    Layout --> Tools
    Tools --> Core
    Tools --> Lib
    Core --> Lib
    REG --- REGDB
```

**关键依赖规则**（阅读代码时的心智模型）：
1. `lib/` 层是叶子 —— 纯函数 + 少量基础设施，工具与布局都依赖它，它不反向依赖任何组件；
2. `logger.ts` 通过 **sink 注入模式**避免 logger → log-store 的循环依赖；
3. 布局层不直接 import 具体工具 —— 只经注册表的 lazy `component`；
4. 跨工具协作全部经 store（如 screenshot-ocr-store 连接截图窗/编辑器/翻译）或 window 事件，工具之间无直接 import；
5. Tauri API 一律动态 import + `isTauri` 判定，保持浏览器可运行。

## 5. 依赖健康度观察

- **零后端 HTTP 依赖的纯本地策略**：所有重计算在前端 JS 或 Rust 本地完成；唯一远程 API 是百度翻译（capability 白名单锁死单一端点）。
- **刻意不引入的库**：GZip 用原生 CompressionStream；SHA 用 WebCrypto；仅 MD5 用 js-md5。
- **react-router-dom 在依赖中但未被使用**（无路由表，导航全靠 Zustand）—— 属于可清理项。
- Windows FFI 全部收敛在 `windows 0.58` 一个 crate，跨平台代码用 `cfg!(windows)` 显式分叉（非 Windows 回退 xcap）。
